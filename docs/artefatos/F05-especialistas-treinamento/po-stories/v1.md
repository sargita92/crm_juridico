# F05 — Treinamento de Especialistas — Stories

## Story 1: Gestao de documentos RAG

### Objetivo de negocio
O admin precisa fazer upload e gerenciar documentos que serao usados como base de conhecimento dos especialistas. Documentos de RAG permitem que o especialista responda com base em informacoes reais do negocio (contratos, legislacoes, FAQs, manuais), sem precisar alterar o prompt manualmente.

### Escopo
**Entra:**
- upload de documentos (PDF, TXT, DOCX) com nome e tipo
- listagem paginada de documentos com busca por nome
- visualizacao de detalhe do documento (nome, tipo, data de upload)
- exclusao de documento (com confirmacao)
- documentos sao recursos globais, reutilizaveis entre especialistas

**Nao entra:**
- processamento/indexacao do conteudo do documento (sera feito quando a IA for integrada)
- preview do conteudo do documento na interface
- versionamento de documentos
- limite de tamanho por tenant (recurso global admin)

### Criterios de aceite
1. Admin consegue fazer upload de um documento informando nome e arquivo
2. Sistema valida que nome nao esta vazio
3. Sistema valida tipos de arquivo permitidos (PDF, TXT, DOCX)
4. Admin consegue listar documentos com paginacao e busca por nome
5. Admin consegue visualizar detalhes de um documento
6. Admin consegue excluir um documento com confirmacao previa
7. Documento excluido que estava associado a especialistas e desassociado automaticamente
8. Mensagens de sucesso e erro sao exibidas adequadamente

## Story 2: Associar documentos RAG a especialistas

### Objetivo de negocio
O admin precisa vincular documentos de conhecimento a especialistas especificos. Um mesmo documento pode ser compartilhado entre varios especialistas (ex: uma legislacao relevante para diferentes areas), evitando duplicacao e facilitando a manutencao.

### Escopo
**Entra:**
- na tela de detalhe do especialista, secao para gerenciar documentos associados
- listar documentos ja associados ao especialista
- associar novos documentos (selecao entre documentos disponiveis)
- desassociar documento de um especialista
- um documento pode estar associado a varios especialistas (N:N)

**Nao entra:**
- ordenacao/priorizacao de documentos por especialista
- configuracao de relevancia ou peso por documento
- upload de documento direto pela tela do especialista (deve usar a gestao de documentos)

### Criterios de aceite
1. Na tela de detalhe do especialista, existe uma secao de "Documentos RAG"
2. Admin consegue ver os documentos ja associados ao especialista
3. Admin consegue associar novos documentos selecionando de uma lista de disponiveis
4. Admin consegue desassociar um documento do especialista
5. Nao e possivel associar o mesmo documento duas vezes ao mesmo especialista
6. Nao e possivel associar documentos a um especialista inativo
7. A lista de documentos disponiveis exclui os ja associados

## Story 3: Gestao de MCPs (servidores de contexto)

### Objetivo de negocio
O admin precisa cadastrar e gerenciar servidores MCP (Model Context Protocol) que fornecem ferramentas e contexto externo aos especialistas. MCPs permitem que o especialista consulte APIs, bancos de dados ou servicos externos durante o atendimento.

### Escopo
**Entra:**
- CRUD de servidores MCP: nome, URL, configuracao (JSON), headers opcionais
- listagem paginada de MCPs com busca por nome
- visualizacao de detalhe do MCP
- edicao de MCP existente
- exclusao de MCP (com confirmacao)
- MCPs sao recursos globais, reutilizaveis entre especialistas

**Nao entra:**
- teste de conectividade com o servidor MCP pela interface
- monitoramento de saude do MCP
- log de chamadas feitas ao MCP

### Criterios de aceite
1. Admin consegue criar um MCP informando nome, URL e configuracao
2. Sistema valida que nome e URL nao estao vazios
3. Sistema valida que URL tem formato valido
4. Admin consegue listar MCPs com paginacao e busca por nome
5. Admin consegue editar um MCP existente
6. Admin consegue excluir um MCP com confirmacao previa
7. MCP excluido que estava associado a especialistas e desassociado automaticamente
8. Mensagens de sucesso e erro sao exibidas adequadamente

- listar MCPs ja associados ao especialista

- desassociar MCP de um especialista

**Nao entra:**
- configuracao especifica do MCP por especialista (mesma config para todos)
- ordenacao ou prioridade de MCPs por especialista

### Criterios de aceite
1. Na tela de detalhe do especialista, existe uma secao de "MCPs"
2. Admin consegue ver os MCPs ja associados ao especialista
3. Admin consegue associar novos MCPs selecionando de uma lista de disponiveis
4. Admin consegue desassociar um MCP do especialista
5. Nao e possivel associar o mesmo MCP duas vezes ao mesmo especialista
6. Nao e possivel associar MCPs a um especialista inativo
7. A lista de MCPs disponiveis exclui os ja associados

## Story 5: Configurar guardrails por especialista

### Objetivo de negocio
O admin precisa definir regras e limites para controlar o comportamento de cada especialista. Guardrails garantem que o agente de IA nao fuja do escopo, nao aborde topicos proibidos e mantenha o tom adequado — essencial para o ambiente juridico onde precisao e conformidade sao criticas.

### Escopo
**Entra:**
- CRUD de guardrails por especialista
- cada guardrail tem: tipo, regra (texto), mensagem de resposta padrao e status (ativo/inativo)
- tipos de guardrail: topicos proibidos, limite de escopo, tom de resposta
- ativacao/desativacao individual de guardrails
- listagem dos guardrails do especialista

**Nao entra:**
- teste de guardrail com simulacao de conversa
- guardrails globais compartilhados entre especialistas (cada especialista tem seus proprios)
- historico de alteracoes nos guardrails

### Criterios de aceite
1. Admin consegue adicionar um guardrail a um especialista com tipo, regra e mensagem
2. Sistema valida que regra nao esta vazia
3. Sistema oferece tipos predefinidos de guardrail (topicos proibidos, limite de escopo, tom de resposta)
4. Admin consegue listar todos os guardrails de um especialista
5. Admin consegue editar um guardrail existente
6. Admin consegue ativar/desativar um guardrail individualmente
7. Admin consegue excluir um guardrail com confirmacao
8. Nao e possivel adicionar guardrails a um especialista inativo

## Story 6: Configurar passo a passo (script de atendimento)

### Objetivo de negocio
O admin precisa definir um roteiro sequencial que o especialista segue durante o atendimento. O passo a passo garante que informacoes essenciais sejam coletadas de forma estruturada (ex: nome do cliente, numero do processo, documento, descricao do caso) antes de qualquer encaminhamento.

### Escopo
**Entra:**
- CRUD de steps por especialista
- cada step tem: ordem, texto (pergunta/instrucao), tipo de dado esperado, obrigatoriedade
- tipos de dado esperado: texto livre, numero, data, documento, selecao
- reordenacao de steps (mover para cima/para baixo)
- listagem ordenada dos steps do especialista

**Nao entra:**
- logica condicional entre steps (ex: "se respondeu X, pular para step Y")
- drag-and-drop (reordenacao por botoes de mover e suficiente)
- teste do fluxo com simulacao de conversa
- pontuacao dos steps (story separada)

### Criterios de aceite
1. Admin consegue adicionar um step com texto, tipo de dado esperado e obrigatoriedade
2. Sistema valida que texto do step nao esta vazio
3. Admin consegue listar todos os steps de um especialista na ordem correta
4. Admin consegue editar um step existente
5. Admin consegue reordenar steps (mover para cima/para baixo)
6. Admin consegue excluir um step com confirmacao
7. Ao excluir um step, os demais sao reordenados automaticamente
8. Nao e possivel adicionar steps a um especialista inativo

## Story 7: Configurar sistema de qualificacao por pontuacao

### Objetivo de negocio
O admin precisa configurar um sistema de pontuacao que qualifica ou desqualifica leads automaticamente com base nas informacoes coletadas pelo especialista durante o atendimento. Isso permite priorizar leads com maior potencial e filtrar os que nao se enquadram no perfil desejado.

### Escopo
**Entra:**
- cada step pode ter uma pontuacao associada (valor numerico >= 0)
- configuracao de scoring por especialista: total de pontos e threshold de qualificacao
- logica: soma dos pontos dos steps completados vs threshold
  - soma >= threshold: lead qualificado
  - soma < threshold: lead desqualificado
- interface para configurar pontuacao de cada step e definir threshold
- visualizacao do resumo de scoring (total possivel, threshold, percentual)

**Nao entra:**
- aplicacao automatica do scoring em leads reais (depende de F06/F07 para integracao com WhatsApp e funil)
- regras de scoring complexas (pesos variaveis, multiplicadores)
- historico de alteracoes no scoring

### Criterios de aceite
1. Admin consegue atribuir pontuacao a cada step do especialista
2. Pontuacao e um valor numerico >= 0
3. Admin consegue definir o threshold de qualificacao por especialista
4. Threshold e um valor numerico > 0
5. Interface exibe o total de pontos possivel (soma de todos os steps)
6. Interface exibe a relacao entre total possivel e threshold
7. Sistema impede threshold maior que o total de pontos possivel
8. Admin consegue alterar pontuacoes e threshold a qualquer momento
9. Alteracoes sao salvas com sucesso e refletidas na interface

## Story 8: Acesso restrito ao admin

### Objetivo de negocio
Todas as funcionalidades de treinamento de especialistas (documentos RAG, MCPs, guardrails, steps e scoring) devem ser acessiveis apenas por administradores, mantendo a seguranca e integridade das configuracoes de IA.

### Escopo
**Entra:**
- todas as rotas de documentos, MCPs, guardrails, steps e scoring restritas ao role "admin"
- usuario comum recebe erro ao tentar acessar
- usuario nao autenticado recebe erro ao tentar acessar

**Nao entra:**
- permissao para tenant visualizar configuracoes dos seus proprios especialistas
- niveis granulares de permissao admin

### Criterios de aceite
1. Apenas usuarios com role "admin" conseguem acessar as rotas de treinamento
2. Usuario com role "user" recebe erro 403 ao tentar acessar qualquer rota de treinamento
3. Usuario nao autenticado recebe erro 401
4. Tentativas de acesso nao autorizado sao registradas em log
