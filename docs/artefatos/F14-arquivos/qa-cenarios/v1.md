# Cenários de Teste — F14 Arquivos por Lead

## Story 1 — Captura automática de arquivos

### CT-01: Receber mensagem com imagem
- **Dado** que o tenant T1 recebeu uma mensagem de imagem (JPEG, 500 KB) do contato C1
- **Quando** o provider whatsmeow processa o evento
- **Então** o arquivo é persistido em `files` com `media_type=image`, `direction=inbound`, `tenant_id=T1`, `contact_id=C1`, `conversation_id` e `message_id` preenchidos
- **E** o conteúdo é gravado no storage sob chave `{tenant_id}/{yyyy}/{mm}/{uuid}.jpg`

### CT-02: Receber mensagem com documento PDF
- **Dado** que o tenant T1 recebeu `contrato.pdf` (1,2 MB)
- **Quando** o provider processa
- **Então** o arquivo é persistido com `media_type=document`, `mime_type=application/pdf`, `name=contrato.pdf`

### CT-03: Receber mensagem com áudio
- **Dado** que o tenant T1 recebeu um áudio OGG de 30 s
- **Quando** o provider processa
- **Então** o arquivo é persistido com `media_type=audio`

### CT-04: Receber mensagem com vídeo
- **Dado** que o tenant T1 recebeu um vídeo MP4 (8 MB)
- **Quando** o provider processa
- **Então** o arquivo é persistido com `media_type=video`

### CT-05: Receber mídia sem lead prévio
- **Dado** que não existe lead para o contato C2 no tenant T1
- **Quando** o provider processa uma imagem recebida
- **Então** o arquivo é persistido com `lead_id=NULL`
- **E** não há erro na ingestão

### CT-06: Receber mídia associa ao lead existente
- **Dado** que existe lead L1 vinculado à conversa Conv1
- **Quando** um documento é recebido em Conv1
- **Então** o arquivo é persistido com `lead_id=L1`

### CT-07: Falha no download da mídia não derruba a mensagem
- **Dado** que o download da mídia falha (erro de rede)
- **Quando** o provider processa a mensagem
- **Então** a `Message` é persistida normalmente (com `Content` vazio ou caption)
- **E** nenhum `File` é criado
- **E** um log de erro é emitido com `tenant_id`, `conversation_id`

### CT-08: Mídia com MIME desconhecido é classificada como `other`
- **Dado** que um arquivo com MIME `application/x-archive` é recebido
- **Quando** o provider processa
- **Então** o arquivo é persistido com `media_type=other`

### CT-09: Isolamento por tenant na captura
- **Dado** que tenant T1 e T2 recebem mídias simultâneas
- **Quando** ambas são processadas
- **Então** cada arquivo fica associado ao seu tenant; nenhum cross-contamination

### CT-10: Tamanho acima do limite é rejeitado
- **Dado** que o limite configurado é 50 MB
- **Quando** uma mídia de 60 MB chega
- **Então** o arquivo NÃO é persistido
- **E** log warn é emitido com `size_bytes` e `tenant_id`

### CT-11 (outbound, hook pronto): StoreOutbound é invocado quando disponível
- **Dado** que o módulo `files` recebe chamada de `StoreOutbound` com bytes
- **Quando** a chamada é feita
- **Então** o arquivo é persistido com `direction=outbound`
- **Obs**: teste unitário do use case/adapter, não depende de F06 ter envio de mídia pronto

## Story 3 — Filtros e busca

### CT-18: Filtrar por tipo `image`
- **Dado** arquivos mistos (5 imagens, 3 documentos)
- **Quando** aplica `?type=image`
- **Então** lista mostra apenas as 5 imagens

### CT-19: Filtrar por período `7d`
- **Dado** arquivos de várias datas
- **Quando** aplica `?period=7d`
- **Então** lista mostra apenas arquivos dos últimos 7 dias

### CT-20: Busca por nome parcial
- **Dado** arquivos `contrato.pdf`, `Contrato-2026.pdf`, `foto.jpg`
- **Quando** aplica `?q=contrato`
- **Então** retorna os 2 arquivos com "contrato" no nome (case-insensitive)

### CT-21: Combinação de filtros
- **Dado** arquivos de vários tipos/datas
- **Quando** aplica `?type=document&period=7d&q=contrato`
- **Então** retorna apenas documentos dos últimos 7 dias com "contrato" no nome

### CT-22: Período custom com datas
- **Dado** arquivos de várias datas
- **Quando** aplica `?period=custom&from=2026-04-01&to=2026-04-10`
- **Então** retorna arquivos do intervalo

### CT-23: `from` depois de `to` retorna 400
- **Dado** filtros inválidos
- **Quando** aplica `?from=2026-04-10&to=2026-04-01`

### CT-24: Filtro por `lead_id`
- **Dado** lead L1 com 4 arquivos

- **Então** lista mostra apenas os 4 arquivos

### CT-25: Filtro `lead_id` de outro tenant retorna vazio

- **Então** lista volta vazia (não retorna dados de T2)

### CT-26: Filtros ativos são exibidos nos chips
- **Dado** filtros `type=image` e `period=7d`
- **Quando** renderiza a lista
- **Então** a barra "filtros ativos" mostra dois chips + botão limpar

## Story 5 — Download de arquivos

### CT-33: Download com nome original
- **Dado** arquivo `contrato.pdf`
- **Quando** clica em baixar
- **Então** response tem `Content-Disposition: attachment; filename*=UTF-8''contrato.pdf`
- **E** corpo da resposta é o conteúdo do arquivo
- **E** `Content-Type` corresponde ao `mime_type` armazenado
- **E** `X-Content-Type-Options: nosniff`

### CT-34: Download registra métrica
- **Dado** download bem-sucedido
- **Quando** o handler responde
- **Então** counter `crm_files_downloads_total` é incrementado

### CT-35: Download cross-tenant retorna 404
- **Dado** file F1 de T1
- **Quando** usuário de T2 solicita
- **Então** resposta é 404

### CT-36: Download de arquivo cuja chave não existe no storage
- **Dado** arquivo no DB mas bytes removidos do disco
- **Quando** solicita download
- **Então** resposta é 500 com mensagem amigável e log de erro

### CT-37: Path traversal não atinge o storage
- **Dado** um atacante tenta forjar um `name="../etc/passwd"`
- **Quando** file é persistido
- **Então** o `storage_key` não contém `..` e o arquivo é gravado sob UUID
- **E** nada fora de `storage_root/{tenant_id}/` é alcançável via API

## Casos de borda resumidos

| # | Borda | Resultado esperado |
|---|-------|--------------------|
| a | filename com acentos (`recibo-água.pdf`) | preserva acentos, download funciona (UTF-8 filename*) |
| b | filename com espaços/caracteres inválidos | sanitizado no `name` e no `storage_key` |
| c | 2 mídias idênticas em sequência | 2 registros distintos (UUIDs próprios) |
| d | `messages.type` já existente antes da migration | migration idempotente (ALTER é safe) |
| e | storage_root inexistente no boot | app falha rápido no startup com erro claro |
| f | lead deletado depois do arquivo | arquivo permanece com `lead_id=NULL` (ON DELETE SET NULL) |
| g | mensagem deletada depois do arquivo | arquivo permanece com `message_id=NULL` |
