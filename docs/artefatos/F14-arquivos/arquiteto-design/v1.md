# Design Técnico — F14 Arquivos por Lead

## Visão geral

F14 cria o módulo `files` em `internal/files/` (domínio + aplicação + infra + interfaces HTTP), responsável pela listagem, preview e download de arquivos trocados pelo WhatsApp.

A **captura automática** de mídia exige estender o módulo `whatsapp` — hoje o provider whatsmeow ignora silenciosamente mensagens com mídia ([whatsmeow_provider.go:272-274](internal/whatsapp/infrastructure/whatsmeow_provider.go#L272)). O `files` module expõe uma interface `FileStorer` que o `whatsapp` passa a chamar ao receber mídia (mesmo padrão de integração F07 usou com `LeadCreator`).

Storage físico usa disco local com interface abstrata para trocar por object storage futuramente. Preview inline server-side (HTMX), sem SPA.

## 1. Domínio

### 1.1 Entidade File

```go
// internal/files/domain/file.go

type MediaType string

const (
    MediaTypeImage    MediaType = "image"
    MediaTypeDocument MediaType = "document"
    MediaTypeAudio    MediaType = "audio"
    MediaTypeVideo    MediaType = "video"
    MediaTypeOther    MediaType = "other"
)

type Direction string

const (
    DirectionInbound  Direction = "inbound"
    DirectionOutbound Direction = "outbound"
)

type File struct {
    ID             string
    TenantID       string
    LeadID         *string   // pode ser nulo (mensagem antes do lead existir)
    ConversationID string
    ContactID      string
    MessageID      *string   // FK opcional p/ whatsapp.messages
    Name           string    // nome original (ou derivado)
    MediaType      MediaType
    MimeType       string
    SizeBytes      int64
    StorageKey     string    // caminho/chave lógica no backend de storage
    Direction      Direction
    CreatedAt      time.Time
    UpdatedAt      time.Time
}

const (
    MaxFileNameLength  = 255
    MaxMimeTypeLength  = 100
    MaxStorageKeyLength = 512
)

func NewFile(
    id, tenantID, conversationID, contactID, name, mimeType, storageKey string,
    sizeBytes int64,
    mediaType MediaType,
    direction Direction,
    leadID, messageID *string,
) (*File, error)
```

#### Validações
- `tenantID`, `conversationID`, `contactID`, `name`, `storageKey` obrigatórios
- `sizeBytes >= 0`
- `mediaType` deve estar no conjunto válido
- `direction` deve estar no conjunto válido
- `name` sanitizado (sem path traversal); a entidade guarda apenas o nome final

#### Classificação de MediaType
`DetectMediaType(mime string) MediaType` — helper puro (sem I/O) que mapeia MIME → enum:
- `image/*` → image
- `application/pdf|msword|vnd.*|text/*` → document
- `audio/*` → audio
- `video/*` → video
- default → other

### 1.4 Storage (porta)

```go
// internal/files/domain/storage.go

type Storage interface {
    // Save persiste os bytes sob a chave lógica. Key inclui tenant_id.
    Save(ctx context.Context, key string, content []byte) error
    // Open abre um reader; caller fecha.
    Open(ctx context.Context, key string) (io.ReadCloser, error)
    // Size retorna o tamanho dos bytes armazenados (para verificação opcional).
    Size(ctx context.Context, key string) (int64, error)

```

Implementação inicial: **LocalDiskStorage** em `internal/files/infrastructure/local_disk_storage.go`, com raiz configurável (`FILES_STORAGE_ROOT`, default `./storage/files`).

Formato da chave: `{tenant_id}/{YYYY}/{MM}/{file_uuid}{ext}`. Ext derivada do MIME (ou do nome original sanitizado).

### Regras comuns
- Todo caso de uso recebe `tenantID` explicitamente e passa ao repo — isolamento no SQL.
- `context.Context` propagado para traces e timeouts.
- Erros de domínio retornados cruas (o handler mapeia para HTTP).

## 3. Contratos HTTP

### 3.1 Páginas (HTML completo)

| Método | Rota | Descrição | Middleware |
|--------|------|-----------|------------|
| GET | /tenant/files | Página da aba Arquivos (lista + filtros) | auth, tenant, `files:view` |

### 3.2 Fragmentos HTMX

| Método | Rota | Descrição | Middleware |
|--------|------|-----------|------------|
| GET | /tenant/files/list | Lista (linhas + paginação) — aceita query params de filtro | auth, tenant, `files:view` |
| GET | /tenant/files/:id/preview | Conteúdo do drawer lateral | auth, tenant, `files:view` |
| GET | /tenant/files/:id/download | Stream do arquivo (Content-Disposition: attachment) | auth, tenant, `files:view` |
| GET | /tenant/files/:id/thumbnail | Stream inline para tag `<img>` (apenas imagens; senão 404) | auth, tenant, `files:view` |
| GET | /tenant/leads/:id/files-summary | Seção "Arquivos (N)" do modal de lead | auth, tenant, `files:view` |

### 3.3 Query params de /tenant/files e /tenant/files/list

| Param | Tipo | Obs |
|-------|------|-----|
| `q` | string | busca parcial por nome |
| `type` | enum | `image`, `document`, `audio`, `video`, `other` |
| `period` | preset | `today`, `7d`, `30d`, `custom` |
| `from`, `to` | ISO date | usados quando `period=custom` |
| `lead_id` | uuid | pré-filtro de lead |
| `page` | int | default 1 |

### 3.4 Respostas
- Todas as rotas com exceção de download/thumbnail retornam **HTML fragment** para HTMX.
- Download usa `Content-Disposition: attachment; filename="<escapado>"` e MIME correto.
- Thumbnail serve o arquivo original para imagens (primeira iteração; sem resize).

### 3.5 Status codes
- 200 OK — recursos válidos do tenant
- 401 Unauthorized — sem sessão
- 403 Forbidden — sem permissão `files:view`
- 404 Not Found — id inexistente OU id de outro tenant (para não vazar existência)
- 400 Bad Request — query params inválidos
- 500 Internal Server Error — falha de storage/DB

## 4. Migration

### 000052_create_files_table

```sql
CREATE TABLE IF NOT EXISTS files (
    id CHAR(36) PRIMARY KEY,
    tenant_id CHAR(36) NOT NULL,
    lead_id CHAR(36) DEFAULT NULL,
    conversation_id CHAR(36) NOT NULL,
    contact_id CHAR(36) NOT NULL,
    message_id CHAR(36) DEFAULT NULL,
    name VARCHAR(255) NOT NULL,
    media_type ENUM('image','document','audio','video','other') NOT NULL DEFAULT 'other',
    mime_type VARCHAR(100) NOT NULL DEFAULT '',
    size_bytes BIGINT NOT NULL DEFAULT 0,
    storage_key VARCHAR(512) NOT NULL,
    direction ENUM('inbound','outbound') NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_files_tenant (tenant_id),
    INDEX idx_files_lead (lead_id),
    INDEX idx_files_conversation (conversation_id),
    INDEX idx_files_tenant_created (tenant_id, created_at),
    INDEX idx_files_tenant_type (tenant_id, media_type),
    CONSTRAINT fk_files_tenant FOREIGN KEY (tenant_id) REFERENCES tenants(id),
    CONSTRAINT fk_files_conversation FOREIGN KEY (conversation_id) REFERENCES conversations(id),
    CONSTRAINT fk_files_contact FOREIGN KEY (contact_id) REFERENCES contacts(id),
    CONSTRAINT fk_files_lead FOREIGN KEY (lead_id) REFERENCES leads(id) ON DELETE SET NULL,
    CONSTRAINT fk_files_message FOREIGN KEY (message_id) REFERENCES messages(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Observações:
- `message_id` e `lead_id` com `ON DELETE SET NULL` para preservar o arquivo mesmo após remoções futuras.
- Índices focados em listagens típicas (por tenant + data, por lead, por tipo).

### Migração complementar no whatsapp (opcional, mesmo step)

Para suportar captura, o campo `messages.type` precisa aceitar novos valores (`image`, `document`, `audio`, `video`). Migration `000053_extend_message_types`:

```sql
ALTER TABLE messages
MODIFY COLUMN type ENUM('text','image','document','audio','video','sticker','other') NOT NULL DEFAULT 'text';
```

### 5.4 Outbound (enviar mídia) — fora de escopo

Hoje o `SendMessage` só suporta texto ([send_message.go:50-117](internal/whatsapp/application/send_message.go#L50)). F14 **expõe o hook** (`StoreOutbound`) mas não altera `SendMessage`. ## 6. Integração com Funnel (Lead lookup)

O `files` module precisa saber o `lead_id` associado a uma conversa na hora de persistir (para facilitar filtros e contagem).

```go
// internal/files/domain/lead_lookup.go
type LeadLookup interface {
    FindByConversation(ctx context.Context, tenantID, conversationID string) (leadID string, found bool, err error)
}
```

Implementado pelo funnel module expondo `funnelMod.LeadLookup()` (adapter fino em cima de `LeadRepository.FindByConversationID`).

Se o arquivo chega antes do lead ser criado (ex: mídia como primeira mensagem que gera o lead), o `StoreFileUseCase` persiste com `LeadID=nil` e um job/fluxo futuro pode backfillar — **fora do escopo v1**. A UI trata `LeadID=nil` exibindo apenas o contato.

type Module struct {
    handler      *httpx.Handler
    pageHandler  *httpx.PageHandler
    fileStorer   domain.FileStorer  // para whatsapp
    leadSummary  *application.LeadFilesSummaryUseCase // para funnel detail

func NewModule(
    db *gorm.DB,
    log *zap.Logger,
    leadLookup domain.LeadLookup,
    permChecker middleware.PermissionChecker,
    storageRoot string,
) *Module {

    repo := infrastructure.NewGormFileRepository(db)

    storeUC := application.NewStoreFileUseCase(repo, storage, leadLookup)
    listUC := application.NewListFilesUseCase(repo)
    getUC := application.NewGetFileUseCase(repo)

    handler := httpx.NewHandler(listUC, getUC, downloadUC, log)
    pageHandler := httpx.NewPageHandler(listUC, log)

    return &Module{
        handler:     handler,
        pageHandler: pageHandler,
        fileStorer:  adapter,
        leadSummary: leadSummaryUC,
    }

## 10. Segurança

- **Path traversal**: `storage_key` sempre derivado de UUIDs; `name` sanitizado com `filepath.Base` + remoção de separadores antes de gravar.
- **Tamanho**: teto de 50 MB por arquivo na captura (mídia do WhatsApp tipicamente <16 MB; margem folgada). Valor configurável `FILES_MAX_BYTES`.
- **Isolamento**: todas as queries recebem `tenant_id`. Handler retorna 404 (não 403) quando ID existe em outro tenant — evita enumeration.
- **Download**: `Content-Disposition: attachment` + `filename*=UTF-8''<encoded>` para suportar acentos. Previne XSS via extensão maliciosa.
- **Thumbnail**: só serve bytes se `media_type == image` — evita servir PDF como imagem inline.
- **MIME sniffing**: `Content-Type` derivado do DB, não do arquivo, para não abrir brecha de polyglot. Adiciona `X-Content-Type-Options: nosniff`.
- **Permissão**: middleware `requirePerm("files", "view")`. Ação `manage` fica reservada para delete (fora de escopo v1).
