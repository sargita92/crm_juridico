# F03 — CRUD de Tenants (Admin) — Stories

## Story 1: Criar tenant

### Objetivo de negocio
O admin precisa cadastrar novos clientes (tenants) no sistema para que eles possam utilizar o CRM. Sem isso, nenhum novo cliente pode ser onboardado.

### Escopo
**Entra:**
- formulario de criacao com nome, tipo (PF/PJ) e documento (CPF/CNPJ)
- validacao de documento unico (nao permitir duplicados)
- tenant criado com status "ativo" por padrao

**Nao entra:**
- upload de logo ou imagens
- configuracao de permissoes do tenant (feature futura)
- associacao com especialistas (F04)

### Criterios de aceite
1. Admin consegue criar um tenant informando nome, tipo e documento
2. Sistema valida que o documento nao esta duplicado
3. Sistema valida que todos os campos obrigatorios estao preenchidos
4. Tenant criado aparece na listagem com status "ativo"
5. Mensagem de sucesso e exibida apos criacao
6. Mensagem de erro e exibida se documento ja existir

---

## Story 2: Listar tenants

### Objetivo de negocio
O admin precisa visualizar todos os tenants cadastrados para gerenciar sua base de clientes. A listagem deve permitir busca e filtragem para facilitar a localizacao em bases grandes.

### Escopo
**Entra:**
- listagem paginada de tenants
- busca por nome ou documento
- filtro por status (ativo, bloqueado, inativo)
- filtro por tipo (PF, PJ)
- exibicao de: nome, tipo, documento, status, data de criacao

**Nao entra:**
- exportacao para CSV/Excel
- ordenacao customizada (ordem padrao: mais recentes primeiro)

### Criterios de aceite
1. Admin ve a lista de tenants com nome, tipo, documento, status e data de criacao
2. Listagem e paginada (ex: 20 por pagina)
3. Admin consegue buscar por nome ou documento
4. Admin consegue filtrar por status
5. Admin consegue filtrar por tipo (PF/PJ)
6. Listagem vazia exibe mensagem adequada ("Nenhum tenant encontrado")
7. Filtros e busca funcionam combinados

---

## Story 3: Visualizar detalhe do tenant

### Objetivo de negocio
O admin precisa ver todas as informacoes de um tenant especifico para tomar decisoes de gestao (editar, bloquear, etc).

### Escopo
**Entra:**
- tela de detalhe com todas as informacoes do tenant
- exibicao de: nome, tipo, documento, status, motivo de bloqueio (se houver), datas de criacao e atualizacao
- acesso as acoes de editar, bloquear/desbloquear

**Nao entra:**
- historico de atividades do tenant
- listagem de usuarios vinculados (feature futura)

### Criterios de aceite
1. Admin consegue acessar o detalhe de um tenant a partir da listagem
2. Todas as informacoes do tenant sao exibidas corretamente
3. Se o tenant esta bloqueado, o motivo do bloqueio e exibido
4. Acoes de editar e bloquear/desbloquear estao acessiveis na tela de detalhe

---

## Story 4: Editar tenant

### Objetivo de negocio
O admin precisa corrigir ou atualizar informacoes de tenants existentes (ex: mudanca de razao social, correcao de documento).

### Escopo
**Entra:**
- edicao de nome, tipo e documento
- validacao de documento unico (excluindo o proprio tenant)
- validacao de campos obrigatorios

**Nao entra:**
- alteracao de status por edicao (bloqueio/desbloqueio tem fluxo proprio)
- edicao em lote

### Criterios de aceite
1. Admin consegue editar nome, tipo e documento de um tenant existente
2. Sistema valida que o documento nao conflita com outro tenant
3. Sistema valida campos obrigatorios
4. Alteracoes sao salvas e refletidas na listagem e no detalhe
5. Mensagem de sucesso e exibida apos edicao
6. Mensagem de erro e exibida se validacao falhar

---

## Story 5: Desativar tenant

### Objetivo de negocio
O admin precisa desativar tenants que nao sao mais clientes, removendo-os da operacao sem excluir seus dados (soft delete).

### Escopo
**Entra:**
- desativacao do tenant (status muda para "inativo")
- confirmacao antes de desativar
- tenant desativado nao aparece na listagem padrao (aparece com filtro de inativos)

**Nao entra:**
- exclusao fisica de dados
- reativacao de tenant (pode ser feito via edicao de status futuramente)

### Criterios de aceite
1. Admin consegue desativar um tenant
2. Sistema pede confirmacao antes de desativar
3. Tenant desativado tem status "inativo"
4. Tenant inativo nao aparece na listagem padrao
5. Tenant inativo aparece ao filtrar por status "inativo"
6. Tenant inativo nao consegue acessar a plataforma

---

## Story 6: Bloquear tenant

### Objetivo de negocio
O admin precisa bloquear temporariamente o acesso de um tenant ao sistema (ex: inadimplencia, violacao de termos), registrando o motivo para auditoria.

### Escopo
**Entra:**
- bloqueio do tenant com motivo obrigatorio
- tenant bloqueado nao consegue acessar a plataforma
- motivo de bloqueio visivel no detalhe do tenant

**Nao entra:**
- notificacao automatica ao tenant sobre o bloqueio
- bloqueio automatico por regras (ex: inadimplencia)

### Criterios de aceite
1. Admin consegue bloquear um tenant
2. Sistema exige motivo de bloqueio (campo obrigatorio)
3. Tenant bloqueado tem status "bloqueado"
4. Tenant bloqueado nao consegue fazer login
5. Motivo de bloqueio e exibido no detalhe do tenant
6. Tenant bloqueado aparece na listagem com indicacao visual de bloqueio

---

## Story 7: Desbloquear tenant

### Objetivo de negocio
O admin precisa restaurar o acesso de um tenant previamente bloqueado, registrando o motivo do desbloqueio para auditoria.

### Escopo
**Entra:**
- desbloqueio do tenant com motivo obrigatorio
- tenant volta ao status "ativo" apos desbloqueio
- motivo de desbloqueio registrado

**Nao entra:**
- historico completo de bloqueios/desbloqueios (simplificado nesta versao)
- notificacao automatica ao tenant

### Criterios de aceite
1. Admin consegue desbloquear um tenant previamente bloqueado
2. Sistema exige motivo de desbloqueio (campo obrigatorio)
3. Tenant desbloqueado volta ao status "ativo"
4. Tenant desbloqueado consegue fazer login novamente
5. Motivo de desbloqueio e registrado no sistema

---

## Story 8: Acesso restrito ao admin

### Objetivo de negocio
Apenas administradores devem poder gerenciar tenants. Usuarios comuns nao podem acessar funcionalidades administrativas para garantir a seguranca e integridade dos dados.

### Escopo
**Entra:**
- todas as operacoes de CRUD de tenants restritas ao role "admin"
- usuario comum recebe erro ao tentar acessar rotas administrativas

**Nao entra:**
- niveis granulares de permissao admin (ex: admin financeiro vs admin geral)
- log de auditoria de acoes administrativas

### Criterios de aceite
1. Apenas usuarios com role "admin" conseguem acessar as rotas /admin/tenants/*
2. Usuario com role "user" recebe erro 403 ao tentar acessar
3. Usuario nao autenticado recebe erro 401
4. Tentativas de acesso nao autorizado sao registradas em log
