# Review de Seguranca — F06 Integracao com WhatsApp

## Resultado: APROVADO (apos correcoes)

## Vulnerabilidades Encontradas e Corrigidas

### 1. Race condition na deduplicacao de mensagens (corrigido)
- **Severidade**: Alta
- **Arquivo**: receive_message.go
- **Problema**: Check-then-act entre FindByWhatsAppMsgID e Create nao era atomico
- **Correcao**: Migration ja tem UNIQUE INDEX em whatsapp_msg_id. Adicionado tratamento graceful no Create — se falhar e o msg ID ja existir, retorna nil (dedup concorrente)
- **Status**: Corrigido

### 2. Resource leak no Connect do provider (corrigido)
- **Severidade**: Media
- **Arquivo**: whatsmeow_provider.go
- **Problema**: Container de store nao era fechado se Upgrade ou GetFirstDevice falhassem
- **Correcao**: Adicionado `container.Close()` nos paths de erro
- **Status**: Corrigido

### 3. Sanitizacao fraca do tenant ID no prefix de tabelas (corrigido)
- **Severidade**: Media
- **Arquivo**: whatsmeow_provider.go
- **Problema**: sanitizeTenantID so removia hifens, poderia permitir caracteres especiais
- **Correcao**: Whitelist regex — apenas [a-zA-Z0-9]
- **Status**: Corrigido

### 4. Validacao de tamanho de mensagem ausente no handler (corrigido)
- **Severidade**: Media
- **Arquivo**: handler.go
- **Problema**: Handler nao validava comprimento antes de chamar use case
- **Correcao**: Adicionado check `len(content) > 4096` no handler (defense in depth — dominio ja valida)
- **Status**: Corrigido

## Vulnerabilidades Aceitas (futuras melhorias)

### 5. CSRF Token
- **Severidade**: Media (mitigada)
- **Mitigacao atual**: Cookie SameSite=Lax + HttpOnly
- **Recomendacao futura**: CSRF tokens explicitos

### 6. Security Headers (CSP, X-Frame-Options)
- **Severidade**: Baixa
- **Recomendacao futura**: Middleware de security headers

### 7. Rate Limiting em endpoints WhatsApp
- **Severidade**: Media
- **Mitigacao atual**: Auth obrigatorio em todas as rotas
- **Recomendacao futura**: Rate limiting por tenant no router

### 8. SSE reconnect pode perder eventos
- **Severidade**: Baixa
- **Mitigacao atual**: Buffer de 100 eventos + polling fallback no HTMX
- **Recomendacao futura**: Log quando eventos sao descartados (buffer cheio)

### 9. Erros do provider expoe detalhes de implementacao
- **Severidade**: Baixa
- **Mitigacao atual**: Handler retorna mensagens genericas ao usuario ("Erro ao enviar mensagem")
- **Recomendacao futura**: Wrap erros do whatsmeow em erros de dominio
