# Cenarios de Teste — F02 Autenticacao e Multitenancy

## Story 1: Cadastro de Tenants no sistema

### CT-1.1: Criar tenant com dados validos

- **Dado** que tenho os dados de um tenant (nome, tipo PJ, CNPJ, status active)
- **Quando** crio o tenant no repositorio
- **Entao** o tenant e persistido com todos os campos
- **E** o ID e gerado automaticamente (UUID)
- **E** created_at e updated_at sao preenchidos

### CT-1.2: Criar tenant PF com CPF

- **Dado** que tenho os dados de um tenant tipo PF com CPF
- **Quando** crio o tenant no repositorio
- **Entao** o tenant e persistido com type = "PF"

### CT-1.3: Consultar tenant por ID

- **Dado** que existe um tenant persistido
- **Quando** busco pelo ID do tenant
- **Entao** recebo o tenant com todos os campos corretos

### CT-1.4: Consultar tenant inexistente

- **Dado** que nao existe tenant com o ID informado
- **Quando** busco pelo ID
- **Entao** recebo erro indicando que o tenant nao foi encontrado

### CT-1.5: Documento duplicado

- **Dado** que existe um tenant com CNPJ "12.345.678/0001-00"
- **Quando** tento criar outro tenant com o mesmo CNPJ
- **Entao** recebo erro de documento duplicado

### CT-1.6: Identificar tenant bloqueado

- **Dado** que existe um tenant com status "blocked" e block_reason preenchido
- **Quando** consulto o tenant
- **Entao** o status e "blocked" e o motivo esta acessivel

### CT-2.5: Consultar usuario por email

- **Entao** recebo o usuario com todos os campos corretos

## Story 3: Login com email e senha

### CT-3.1: Login com credenciais validas (happy path)

- **Dado** que existe um usuario ativo com email "joao@email.com" e senha "secret123"
- **Quando** faco POST /login com email e senha corretos
- **Entao** recebo status 200
- **E** cookie "token" e setado com JWT valido
- **E** o JWT contem claims user_id e role

### CT-3.2: Login com senha incorreta

- **Dado** que existe um usuario com email "joao@email.com"
- **Quando** faco POST /login com senha errada
- **Entao** recebo HTML do card de login com mensagem "Email ou senha invalidos"
- **E** a mensagem NAO revela que especificamente a senha esta errada

### CT-3.3: Login com email inexistente

- **Dado** que nao existe usuario com email "naoexiste@email.com"
- **Quando** faco POST /login com esse email
- **Entao** recebo a mesma mensagem generica "Email ou senha invalidos"
- **E** o tempo de resposta e similar ao de senha incorreta (timing-safe)

### CT-3.4: Login com usuario inativo

- **Dado** que existe um usuario com status "inactive"
- **Quando** faco POST /login com credenciais corretas
- **Entao** recebo mensagem de erro (usuario inativo ou credenciais invalidas)

### CT-3.5: Login com 1 tenant — redirect direto

- **Dado** que o usuario tem exatamente 1 tenant
- **Quando** faz login com sucesso
- **Entao** recebo HX-Redirect para /dashboard (nao para /select-tenant)
- **E** o cookie token ja contem tenant_id

### CT-3.6: Login com N tenants — redirect para selecao

- **Dado** que o usuario tem mais de 1 tenant
- **Quando** faz login com sucesso
- **Entao** recebo HX-Redirect para /select-tenant
- **E** o cookie token NAO contem tenant_id ainda

### CT-3.7: Token tem tempo de expiracao

- **Dado** que faco login com sucesso
- **Quando** inspeciono o JWT gerado
- **Entao** o claim "exp" esta presente
- **E** a expiracao corresponde a configuracao (default 24h)

### CT-3.8: Endpoint protegido sem token

- **Dado** que NAO tenho cookie de token
- **Quando** acesso GET /select-tenant
- **Entao** recebo 401

### CT-3.9: Endpoint protegido com token expirado

- **Dado** que tenho um token com expiracao no passado
- **Quando** acesso um endpoint protegido
- **Entao** recebo 401

### CT-3.10: Renderizar tela de login

- **Dado** que acesso GET /login
- **Quando** a pagina e renderizada
- **Entao** vejo campos de email e senha
- **E** botao "Entrar"
- **E** nenhuma mensagem de erro visivel

## Story 4: Isolamento de dados por tenant

### CT-4.1: Query filtrada por tenant automaticamente

- **Dado** que existem dados do tenant A e do tenant B
- **E** o usuario autenticado pertence ao tenant A
- **Quando** o TenantScope e aplicado na query
- **Entao** somente dados do tenant A sao retornados

### CT-4.2: Usuario do tenant A nao acessa dados do tenant B

- **Dado** que existem 2 tenants com dados proprios
- **E** o usuario esta autenticado no tenant A
- **Quando** tenta buscar dados (com TenantScope)
- **Entao** dados do tenant B NAO aparecem nos resultados

### CT-4.3: Admin acessa dados de qualquer tenant

- **Dado** que o usuario tem role "admin"
- **E** selecionou o tenant B
- **Quando** busca dados com TenantScope
- **Entao** recebe dados do tenant B

### CT-4.4: Admin bypassa filtro quando sem tenant

- **Dado** que o usuario tem role "admin"
- **E** NAO selecionou tenant (TenantScope com admin sem tenant_id)
- **Quando** busca dados
- **Entao** recebe dados de todos os tenants

### CT-4.5: Middleware RequireTenant bloqueia sem tenant

- **Dado** que o usuario esta autenticado mas NAO selecionou tenant
- **Quando** acessa rota protegida por RequireTenant
- **Entao** recebe 403

### CT-4.6: Middleware RequireTenant permite com tenant

- **Dado** que o usuario esta autenticado e selecionou tenant
- **Quando** acessa rota protegida por RequireTenant
- **Entao** a requisicao prossegue normalmente

## Cenarios OWASP

### A01 — Broken Access Control

### CT-OWASP-01: Endpoint protegido sem token retorna 401

- **Dado** que NAO envio cookie/header de autenticacao
- **Quando** acesso GET /select-tenant, POST /select-tenant, POST /logout, GET /dashboard
- **Entao** todos retornam 401

### CT-OWASP-02: Usuario comum nao acessa como admin

- **Dado** que o usuario tem role "user"
- **Quando** tenta acessar endpoint restrito a admin (se houver)
- **Entao** recebe 403

### CT-OWASP-03: Isolamento de tenant — cross-tenant access

- **Dado** que usuario do tenant A tenta forjar tenant_id do tenant B no request
- **Quando** envia POST /select-tenant com tenant_id do tenant B
- **Entao** recebe 403 (nao pertence ao tenant)

---

### A02 — Cryptographic Failures

### CT-OWASP-04: Senha hasheada no banco

- **Dado** que crio um usuario com senha "password123"
- **Quando** consulto diretamente o banco (campo password_hash)
- **Entao** o valor NAO e "password123"
- **E** comeca com "$2a$" ou "$2b$" (prefixo bcrypt)

### CT-OWASP-05: JWT nao expoe dados sensiveis

- **Dado** que gero um JWT apos login
- **Quando** decodifico o payload (base64)
- **Entao** NAO contem senha, email ou dados pessoais
- **E** contem apenas user_id, role, tenant_id e timestamps

### CT-OWASP-06: Cookie token com flags de seguranca

- **Dado** que faco login com sucesso
- **Quando** inspeciono o cookie "token"
- **Entao** o cookie tem HttpOnly = true
- **E** SameSite = Strict ou Lax
- **E** Path = "/"

---

### A03 — Injection

### CT-OWASP-07: SQL injection no login

- **Dado** que envio email = `' OR 1=1 --` e password = "qualquer"
- **Quando** faco POST /login
- **Entao** recebo erro de credenciais invalidas (nao executa injection)
- **E** nenhum dado e vazado

### CT-OWASP-08: SQL injection na selecao de tenant

- **Dado** que envio tenant_id = `'; DROP TABLE tenants; --`
- **Quando** faco POST /select-tenant
- **Entao** recebo erro (UUID invalido)
- **E** tabela tenants permanece intacta

---
