# Arquiteto — F21 Design Técnico

## Premissas
- Sem alteração arquitetural; apenas tooling, deps, tests e docs
- Sem novas migrations
- Sem novas rotas HTTP
- Tests existentes devem manter-se verdes a cada step

## Ferramentas

| Tool | Versão alvo | Uso |
|---|---|---|
| `golangci-lint` | já instalado | lint |
| `govulncheck` | latest (instalar via `go install`) | CVE scan |
| `go vet` | nativo | vet |
| `go test` | nativo | testes/cobertura |
| `gocov` ou `go tool cover` | nativo | cobertura por pacote |

`govulncheck` será instalado em Step 1 via `go install golang.org/x/vuln/cmd/govulncheck@latest` no host de dev e no CI.

## Entregáveis por Step

### Step 1 — Tooling: `make audit`
**Arquivos:**
- `Makefile` (novo) — alvos `audit`, `audit-cover`, `audit-vuln`, `audit-lint`, `audit-vet`, `audit-deps`, `audit-todos`
- `.golangci.yml` (novo) — configuração base (linters: errcheck, govet, ineffassign, staticcheck, unused, gosec, gocyclo, misspell)
- `scripts/audit.sh` (novo) — orquestra agregação e gera saída estruturada

**Convenções:**
- Cada sub-alvo é independente e idempotente
- `make audit` chama todos em sequência e retorna não-zero se algum falhar
- Pacotes ignorados pela cobertura: `cmd/api`, `internal/*/module.go`, e *_mock.go (configurável)

### Step 2 — Relatório inicial
**Arquivos:**
- `docs/manutencao/audit-inicial-2026-05-07.md` (novo) — captura do estado atual

**Conteúdo:**
- Cobertura por pacote + total
- Lista de vulnerabilidades
- Top warnings de lint
- Deps desatualizadas (minor/patch)
- TODOs/FIXMEs com idade

### Step 3 — Vulnerabilidades
- Aplicar `go get -u <pkg>@<safe>` para cada CVE
- Rodar `go mod tidy`
- `govulncheck ./...` → 0 achados
- `go test ./...` continua passando

### Step 4 — Deps minor/patch
- Atualizar minor/patch (não major)
- Verificar com `go list -m -u all` (output filtrado)
- Validar build + testes

### Step 5 — Cobertura por pacote
- Identificar pacotes < 80% via Step 1
- Adicionar testes (TDD: red → green) por pacote
- Pacotes infraestrutura GORM: integração com testcontainers se necessário
- Pacotes wiring/main isentos

### Step 6 — Lint/vet
- Configurar `.golangci.yml` final
- Corrigir warnings um a um (não silenciar)
- `go vet ./...` clean

### Step 7 — Código morto e TODOs
- `staticcheck` U1000 (unused) — remover funções, vars, types não usados
- `grep -rE "TODO|FIXME"` com idade via `git blame` — fechar > 90 dias

### Step 8 — Gates CI
**Arquivo:**
- `.github/workflows/ci.yml` (atualização)

**Adições:**
- Job `audit` que chama `make audit`
- Step de cobertura mínima (script `scripts/check-coverage.sh` ou inline)
- Falha o workflow em qualquer achado

### Step 9 — Documentação processo
**Arquivo:**
- `docs/processo/manutencao-tecnica.md` (novo)

**Seções:**
- Cadência (trimestral)
- Responsável (rotação ou fixo)
- Checklist
- Modelo de relatório
- Como executar

### Step 10 — Fechamento
- `make audit` final
- `docs/manutencao/audit-final-YYYY-MM-DD.md` com diff antes/depois
- Atualizar:
  - `docs/processo/backlog.md` → F21 concluído
  - `docs/features/F21-saneamento-tecnico.md` → marcar checkboxes
  - `docs/processo/changelog.md` → entrada
  - `CLAUDE.md` → referência ao processo
- Abrir PR

## Riscos & mitigações

| Risco | Mitigação |
|---|---|
| Update de dep quebra teste | TDD: rodar suite após cada `go get -u`. Reverter se quebrar. |
| Cobertura não sobe sem refactor | Marcar pacote como "não-meta" só se for wiring/main. Caso contrário, escrever teste. |
| `golangci-lint` muito rigoroso → muitas mudanças | Iniciar com linters core (errcheck, govet, staticcheck, unused). Adicionar gradualmente. |
| Tempo total alto | Steps independentes; cada step = commit atômico para retomada |

## Definition of Done
Conforme `docs/features/F21-saneamento-tecnico.md` (critérios de aceite) + DoD por step e por feature em `docs/processo/definition-of-done.md`.
