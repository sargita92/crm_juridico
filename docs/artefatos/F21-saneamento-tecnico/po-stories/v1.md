# PO Stories — F21 Saneamento Técnico

## Contexto de negócio

22 features entregues acumularam dívida técnica mecânica. Antes de F20 (Meta provider em produção) precisamos garantir que vulnerabilidades, cobertura, lint e código morto não afetem a próxima entrega crítica. Esta feature **não agrega função** — agrega confiabilidade e velocidade futura.

## Stories

### S1 — Visibilidade da saúde técnica
**Como** mantenedor do projeto
**Quero** rodar um único comando (`make audit`)
**Para** ver, em segundos, todos os indicadores de saúde do código (cobertura, vulnerabilidades, lint, deps desatualizadas, código morto, TODOs)

**Aceite:**
- `make audit` existe e roda em < 3 min
- Saída agrega: cobertura por pacote + total, govulncheck, golangci-lint, go vet, deps com update disponível, TODOs com idade
- Falha com exit ≠ 0 se houver achado crítico

### S2 — Zerar vulnerabilidades
**Como** responsável de segurança
**Quero** que `govulncheck` retorne zero achados
**Para** não levar CVE conhecida para produção

**Aceite:**
- `govulncheck ./...` → 0 achados
- Updates de deps com CVE aplicados
- Suite de testes continua passando

### S3 — Subir cobertura ao nível mínimo
**Como** mantenedor
**Quero** que todo pacote tenha ≥ 80% de cobertura e que o global esteja ≥ 85%
**Para** que regressões sejam pegas pelo CI

**Aceite:**
- `go test -cover ./...` mostra cobertura ≥ 80% em cada pacote produtivo
- Cobertura global ≥ 85%
- Pacotes de wiring/main isentos da meta

### S4 — Higiene mecânica
**Como** mantenedor
**Quero** zero warnings de lint/vet, código morto removido e TODOs > 90 dias fechados
**Para** que novas mudanças sejam revisáveis sem ruído

**Aceite:**
- `golangci-lint run` → 0 issues
- `go vet ./...` → 0 issues
- Sem código morto encontrado por análise estática
- 0 TODOs/FIXMEs com idade > 90 dias

### S5 — Gates automáticos no CI
**Como** time
**Queremos** que o CI quebre o build se cobertura cair, vulnerabilidade aparecer ou lint warn
**Para** evitar regressão imediata após esta faxina

**Aceite:**
- Workflow `ci.yml` rodando `govulncheck`, `golangci-lint`, `go vet`, cobertura mínima
- PR com queda de cobertura é bloqueado
- PR com vulnerabilidade nova é bloqueado

### S6 — Processo recorrente
**Como** time
**Queremos** um documento que define como reaplicar este processo trimestralmente
**Para** que a faxina não vire one-shot esquecido

**Aceite:**
- `docs/processo/manutencao-tecnica.md` existe
- Define cadência (trimestral), responsável, checklist, modelo de relatório
- Referenciado em `CLAUDE.md` e backlog

## Não-escopo (vira F23+)
- Refactors arquiteturais (quebrar arquivos grandes, extrair pacotes)
- Updates major (Gin v1→v2, etc.)
- Migrações de stack
- Otimização de performance
