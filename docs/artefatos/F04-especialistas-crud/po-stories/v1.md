# F04 — CRUD de Especialistas (Admin) — Stories

## Story 1: Criar especialista

### Objetivo de negocio
O admin precisa cadastrar novos especialistas (agentes de IA) no sistema para que possam ser associados a tenants e futuramente atender leads via WhatsApp. Sem isso, nenhum tenant pode ter atendimento automatizado por IA.

### Escopo
**Entra:**
- formulario de criacao com nome, descricao e status
- campo de texto para o prompt do especialista
- validacao de campos obrigatorios (nome e prompt nao podem ser vazios)
- especialista criado com status "ativo" por padrao

**Nao entra:**
- associacao com tenants (story separada)
- configuracao de RAG, MCPs, guardrails ou steps (F05)
- sistema de qualificacao por pontuacao (F05)

### Criterios de aceite
1. Admin consegue criar um especialista informando nome, descricao e prompt
2. Sistema valida que nome e prompt nao estao vazios
3. Sistema valida tamanho maximo do prompt (ex: 10.000 caracteres)
4. Especialista criado aparece na listagem com status "ativo"
5. Mensagem de sucesso e exibida apos criacao
6. Mensagem de erro e exibida se validacao falhar

---

## Story 2: Listar especialistas

### Objetivo de negocio
O admin precisa visualizar todos os especialistas cadastrados para gerencia-los. A listagem deve permitir busca e filtragem para facilitar a localizacao.

### Escopo
**Entra:**
- listagem paginada de especialistas
- busca por nome
- filtro por status (ativo, inativo)
- exibicao de: nome, descricao (truncada), status, quantidade de tenants associados, data de criacao

**Nao entra:**
- exportacao para CSV/Excel
- ordenacao customizada (ordem padrao: mais recentes primeiro)

### Criterios de aceite
1. Admin ve a lista de especialistas com nome, descricao, status, tenants associados e data de criacao
2. Listagem e paginada (ex: 20 por pagina)
3. Admin consegue buscar por nome
4. Admin consegue filtrar por status
5. Listagem vazia exibe mensagem adequada ("Nenhum especialista encontrado")
6. Filtros e busca funcionam combinados

---

## Story 3: Visualizar detalhe do especialista

### Objetivo de negocio
O admin precisa ver todas as informacoes de um especialista especifico para tomar decisoes de gestao (editar, desativar, verificar prompt, ver tenants associados).

### Escopo
**Entra:**
- tela de detalhe com todas as informacoes do especialista
- exibicao de: nome, descricao, status, prompt completo, datas de criacao e atualizacao
- lista de tenants associados ao especialista
- acesso as acoes de editar e desativar

**Nao entra:**
- historico de alteracoes do prompt (pode ser adicionado futuramente)
- metricas de uso do especialista

### Criterios de aceite
1. Admin consegue acessar o detalhe de um especialista a partir da listagem
2. Todas as informacoes do especialista sao exibidas corretamente
3. Prompt completo e exibido de forma legivel
4. Lista de tenants associados e exibida
5. Acoes de editar e desativar estao acessiveis na tela de detalhe

---

## Story 4: Editar especialista

### Objetivo de negocio
O admin precisa corrigir ou atualizar informacoes de especialistas existentes (ex: ajustar nome, descricao ou refinar o prompt de atendimento).

### Escopo
**Entra:**
- edicao de nome, descricao e prompt
- validacao de campos obrigatorios (nome e prompt nao vazios)
- validacao de tamanho maximo do prompt

**Nao entra:**
- alteracao de status por edicao (desativacao tem fluxo proprio)
- edicao em lote
- versionamento de prompt (pode ser adicionado futuramente)

### Criterios de aceite
1. Admin consegue editar nome, descricao e prompt de um especialista existente
2. Sistema valida campos obrigatorios
3. Sistema valida tamanho maximo do prompt
4. Alteracoes sao salvas e refletidas na listagem e no detalhe
5. Mensagem de sucesso e exibida apos edicao
6. Mensagem de erro e exibida se validacao falhar

---

## Story 5: Desativar especialista

### Objetivo de negocio
O admin precisa desativar especialistas que nao devem mais ser utilizados, removendo-os da operacao sem excluir seus dados ou historico.

### Escopo
**Entra:**
- desativacao do especialista (status muda para "inativo")
- confirmacao antes de desativar
- especialista desativado nao aparece na listagem padrao (aparece com filtro de inativos)
- especialista desativado nao pode ser associado a novos tenants

**Nao entra:**
- exclusao fisica de dados
- desassociacao automatica de tenants ao desativar (tenants mantem a associacao, mas especialista nao atende)

### Criterios de aceite
1. Admin consegue desativar um especialista
2. Sistema pede confirmacao antes de desativar
3. Especialista desativado tem status "inativo"
4. Especialista inativo nao aparece na listagem padrao
5. Especialista inativo aparece ao filtrar por status "inativo"
6. Especialista inativo nao pode ser associado a novos tenants

---

## Story 6: Reativar especialista

### Objetivo de negocio
O admin precisa reativar um especialista previamente desativado para que ele volte a estar disponivel para associacao e atendimento.

### Escopo
**Entra:**
- reativacao do especialista (status volta para "ativo")
- especialista reativado volta a aparecer na listagem padrao

**Nao entra:**
- reassociacao automatica com tenants que tinham o especialista antes da desativacao

### Criterios de aceite
1. Admin consegue reativar um especialista previamente desativado
2. Especialista reativado volta ao status "ativo"
3. Especialista reativado aparece na listagem padrao
4. Especialista reativado pode ser associado a tenants novamente

---

## Story 7: Associar especialista a tenants

### Objetivo de negocio
O admin precisa vincular especialistas a tenants para que cada tenant tenha acesso aos agentes de IA que irao atender seus leads. Um especialista pode atender varios tenants e um tenant pode ter varios especialistas.

### Escopo
**Entra:**
- associar um especialista a um ou mais tenants (multi-select)
- desassociar especialista de um tenant
- visualizar tenants associados a um especialista
- visualizar especialistas associados a um tenant

**Nao entra:**
- configuracao de prioridade entre especialistas de um tenant
- limite de especialistas por tenant
- configuracao especifica do especialista por tenant (mesma config para todos)

### Criterios de aceite
1. Admin consegue associar um especialista a um ou mais tenants
2. Admin consegue desassociar um especialista de um tenant
3. Na tela de detalhe do especialista, os tenants associados sao exibidos
4. Na tela de detalhe do tenant, os especialistas associados sao exibidos
5. Nao e possivel associar um especialista inativo a um tenant
6. Nao e possivel associar um especialista a um tenant inativo ou bloqueado
7. Associacao duplicada e impedida (mesmo especialista + mesmo tenant)

---

## Story 8: Editar prompt do especialista

### Objetivo de negocio
O prompt e o coracao do especialista — define como ele se comporta ao atender leads. O admin precisa de uma interface dedicada e confortavel para editar o prompt, com validacao para evitar erros.

### Escopo
**Entra:**
- campo de texto rico (ou area de texto grande) para edicao do prompt
- validacao de nao vazio
- validacao de tamanho maximo
- preview do prompt antes de salvar (opcional, recomendado)

**Nao entra:**
- versionamento de prompt com historico completo (pode ser adicionado em F05 ou iteracao futura)
- teste do prompt com simulacao de conversa
- variaveis dinamicas no prompt

### Criterios de aceite
1. Admin consegue editar o prompt do especialista em um campo de texto dedicado
2. Campo de texto tem tamanho adequado para prompts longos
3. Sistema valida que o prompt nao esta vazio
4. Sistema valida tamanho maximo do prompt
5. Alteracoes sao salvas com sucesso
6. Mensagem de sucesso e exibida apos salvar

---

## Story 9: Acesso restrito ao admin

### Objetivo de negocio
Apenas administradores devem poder gerenciar especialistas. Usuarios comuns e tenants nao podem acessar funcionalidades de gestao de especialistas para garantir a seguranca e integridade do sistema.

### Escopo
**Entra:**
- todas as operacoes de CRUD de especialistas restritas ao role "admin"
- usuario comum recebe erro ao tentar acessar rotas de especialistas
- usuario nao autenticado recebe erro ao tentar acessar

**Nao entra:**
- niveis granulares de permissao admin
- permissao de tenant para visualizar seus proprios especialistas (feature futura)

### Criterios de aceite
1. Apenas usuarios com role "admin" conseguem acessar as rotas /admin/specialists/*
2. Usuario com role "user" recebe erro 403 ao tentar acessar
3. Usuario nao autenticado recebe erro 401
4. Tentativas de acesso nao autorizado sao registradas em log
