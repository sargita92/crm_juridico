# Cenarios de Teste — F12 Logs (Admin)

## Convencoes

- IDs no formato `S<story>-C<nn>` (ex.: `S1-C01`).
- Cada cenario indica o **tipo de teste automatizado** alvo: `unit` | `integration` | `http` | `e2e manual`.
- Cenarios marcados com **CRITICO** sao obrigatorios para atingir cobertura >= 80% nos pacotes `domain`/`application`/`infrastructure`/`interfaces/http`.
- Toda referencia a `RegisterAuditLog`, `BuildDiff`, `Action`, `AuditPublisher`, `mw.AdminOr404` segue o design do Arquiteto (`arquiteto-design/v1.md`).
- IDs ficticios usados nos exemplos (todos UUID v4):
  - Tenant A: `aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa`
  - Tenant B: `bbbbbbbb-bbbb-4bbb-bbbb-bbbbbbbbbbbb`
  - Admin global: `9f1c0a36-1234-4abc-9abc-9999999abcde` (`admin@crm.com`)
  - Admin secundario: `8e2b1c47-2345-4def-8def-8888888fedcb` (`ana@crm.com`)
  - User tenant (nao-admin): `7d3a2b58-3456-4123-8123-7777777aaaaa`
  - Log id: `01HK0F0F0F0F0F0F0F0F0F0F0F` (placeholder)

## Story 1 — Registro automatico de acoes admin/seguranca

### Happy path

#### S1-C01 [CRITICO] [unit] Login admin com sucesso registra `auth.login.success`

- **Dado** que o admin global `admin@crm.com` envia credenciais validas para `POST /admin/login`
- **E** que o `RequestMeta` injeta `IP=200.123.45.10` e `UserAgent=Mozilla/5.0`
- **Quando** o `LoginUseCase.Execute` retorna sucesso e o handler chama `publisher.Publish`
- **Entao** um `AuditLog` e persistido com:
  - `action="login.success"`
  - `actor_email="admin@crm.com"`
  - `user_id` igual ao id do admin
  - `tenant_id=NULL`
  - `entity="session"`, `entity_id=NULL`
  - `ip="200.123.45.10"`, `user_agent="Mozilla/5.0"`
  - `metadata={}` (sanitizado)
- **E** `crm_audit_logs_registered_total{action="login.success",status="success"}` incrementa em 1.
- **Tipo:** `unit` (mock repo) + `integration` (verifica row em `audit_logs`).

#### S1-C02 [CRITICO] [http] Logout do admin registra `auth.logout`

- **Dado** que o admin global esta autenticado
- **Quando** chama `POST /admin/logout`
- **Entao** um `AuditLog` e gravado com `action="logout"`, `actor_email="admin@crm.com"`, `entity="session"`, `metadata={}`.
- **Tipo:** `http`.

#### S1-C03 [CRITICO] [unit] Criacao de tenant registra `tenant.created`

- **Dado** que admin chama `tenant.CreateTenantUseCase.Execute` com `name="Escritorio Silva", type="PJ"`
- **Quando** o use case persiste o tenant com sucesso (commit OK) e chama `publisher.Publish`
- **Entao** `AuditLog` gravado com `action="tenant.created"`, `entity="tenant"`, `entity_id=<id_novo>`, `tenant_id=<id_novo>`, `metadata={"name":"Escritorio Silva","type":"PJ"}`.
- **Tipo:** `unit` (mock publisher recebe input correto).

#### S1-C04 [CRITICO] [unit] Update de tenant registra `tenant.updated` com diff

- **Dado** que tenant `aaaaaaaa-...` tem `name="Silva"`, `email="x@silva.com"`, `status="ativo"`
- **Quando** admin atualiza para `name="Silva & Cia"`, `email="x@silvaecia.com"`, `status="ativo"` (sem mudar status)
- **Entao** `AuditLog` gravado com `action="tenant.updated"` e `metadata.fields={"name":{"before":"Silva","after":"Silva & Cia"},"email":{"before":"x@silva.com","after":"x@silvaecia.com"}}`.
- **E** `status` NAO aparece no diff (sem mudanca).
- **Tipo:** `unit` (`BuildDiff`) + `integration` (registro persistido).

#### S1-C05 [unit] Desativacao de tenant registra `tenant.deactivated`

- **Dado** que tenant ativo
- **Quando** admin chama `DeactivateTenantUseCase`
- **Entao** `AuditLog` com `action="tenant.deactivated"`, `entity="tenant"`, `entity_id=<id>`, `tenant_id=<id>`, `metadata={}`.
- **Tipo:** `unit`.

#### S1-C06 [CRITICO] [unit] Bloqueio de tenant registra `tenant.blocked` com motivo

- **Dado** que tenant ativo
- **Quando** admin executa `BlockTenantUseCase` com `reason="Inadimplencia 60d"`
- **Entao** `AuditLog` com `action="tenant.blocked"`, `tenant_id=<id>`, `metadata={"reason":"Inadimplencia 60d"}`.
- **Tipo:** `unit`.

#### S1-C07 [unit] Desbloqueio de tenant registra `tenant.unblocked`

- **Dado** que tenant bloqueado
- **Quando** admin chama `UnblockTenantUseCase` com `reason="Pagamento recebido"`
- **Entao** `AuditLog` com `action="tenant.unblocked"` e `metadata.reason` preservado.
- **Tipo:** `unit`.

#### S1-C08 [CRITICO] [unit] Criacao de usuario admin registra `user_admin.created`

- **Dado** que admin chama `auth.ManageUsersUseCase.Create` com `role="admin"`, `name="Ana"`, `email="ana@crm.com"`
- **Quando** persistencia bem-sucedida
- **Entao** `AuditLog` com `action="user_admin.created"`, `entity="user_admin"`, `entity_id=<id_novo>`, `tenant_id=NULL`, `metadata={"name":"Ana","email":"ana@crm.com"}`.
- **Tipo:** `unit`.

#### S1-C09 [unit] Update de usuario admin registra `user_admin.updated` com diff

- **Dado** que admin `ana@crm.com` tem `name="Ana"`, `email="ana@crm.com"`
- **Quando** admin altera `name="Ana Souza"`
- **Entao** `AuditLog` com `action="user_admin.updated"`, `metadata.fields={"name":{"before":"Ana","after":"Ana Souza"}}`.
- **Tipo:** `unit`.

#### S1-C10 [unit] Desativacao/bloqueio/desbloqueio de usuario admin registra acao correspondente

- **Dado** admin alvo `ana@crm.com`
- **Quando** admin executa deactivate/block/unblock (com motivo quando aplicavel)
- **Entao** `AuditLog` com `action` correspondente (`user_admin.deactivated|blocked|unblocked`), `metadata.reason` preservado em block/unblock.
- **Tipo:** `unit`.

#### S1-C11 [CRITICO] [unit] Alteracao de permissao de admin registra `permission.changed` com diff de papel/grupo/perfil

- **Dado** que `ana@crm.com` (admin) tem `role="operador", group="suporte", view_profile="padrao"`
- **Quando** admin altera para `role="gestor", group="comercial", view_profile="avancado"`
- **Entao** `AuditLog` com `action="permission.changed"`, `entity="user_admin"`, `entity_id=<id_ana>`, `metadata={"role":{"before":"operador","after":"gestor"},"group":{"before":"suporte","after":"comercial"},"view_profile":{"before":"padrao","after":"avancado"}}`.
- **Tipo:** `unit`.

### Casos de borda

#### S1-C12 [CRITICO] [unit] Falha de login com senha errada registra `auth.login.failure` (user_id NULL)

- **Dado** que email `admin@crm.com` existe mas senha esta errada
- **Quando** `LoginUseCase` retorna `ErrInvalidCredentials`
- **Entao** `AuditLog` com `action="login.failure"`, `user_id=NULL`, `actor_email="admin@crm.com"`, `metadata={"reason":"invalid_credentials"}`, `ip` preenchido.
- **Tipo:** `unit` + `integration` (linha persistida).

#### S1-C13 [CRITICO] [unit] Falha de login com email inexistente registra `auth.login.failure` com user_id NULL

- **Dado** que email `naoexiste@x.com` nao consta na base
- **Quando** `LoginUseCase` retorna `ErrUserNotFound`
- **Entao** `AuditLog` com `action="login.failure"`, `user_id=NULL`, `actor_email="naoexiste@x.com"` (snapshot do form), `metadata={"reason":"user_not_found"}`.
- **Tipo:** `unit`.

#### S1-C14 [unit] Falha de login com usuario bloqueado registra `auth.login.failure` com `reason="user_blocked"`

- **Dado** que `admin@crm.com` esta com flag bloqueado
- **Quando** `LoginUseCase` retorna `ErrUserBlocked`
- **Entao** `metadata.reason="user_blocked"`, `user_id` preenchido (usuario existe), `actor_email` preserva email tentado.
- **Tipo:** `unit`.

#### S1-C15 [unit] Permissao alterada de usuario nao-admin (role="user") NAO registra log

- **Dado** que alvo da alteracao de permissao tem `role="user"` (tenant)
- **Quando** `permission.ManagePermissionsUseCase` executa
- **Entao** `publisher.Publish` NAO e chamado (escopo MVP — auditoria operacional fora).
- **Tipo:** `unit`.

#### S1-C16 [unit] CRUD operacional do tenant (lead, produto, automacao) NAO gera audit log F12

- **Dado** que admin de tenant cria lead/produto/automacao
- **Quando** o use case persiste
- **Entao** nenhum `AuditLog` da F12 e criado (escopo MVP).
- **Tipo:** `unit` (verifica que o publisher nao recebeu chamada).

### Casos de erro

#### S1-C17 [CRITICO] [unit] Falha ao gravar audit log NAO aborta operacao de negocio

- **Dado** que `BlockTenantUseCase` chama `publisher.Publish` apos commit do tenant bloqueado
- **E** que o `AuditLogRepository.Create` retorna `errors.New("db down")`
- **Quando** o publisher trata o erro internamente
- **Entao** `BlockTenantUseCase.Execute` retorna `nil` (sucesso)
- **E** o tenant esta efetivamente bloqueado no banco
- **E** Zap registra `WARN` com `audit log persist failed`
- **E** `crm_audit_logs_registered_total{action="tenant.blocked",status="error"}` incrementa em 1.
- **Tipo:** `unit` (mock publisher com `repo.Create` retornando erro).

#### S1-C18 [unit] Operacao de negocio que falha NAO gera audit log

- **Dado** que `tenant.UpdateTenantUseCase` falha ao persistir (erro de banco)
- **Quando** o use case retorna erro antes do `Publish`
- **Entao** nenhum `AuditLog` e gerado.
- **Tipo:** `unit`.

#### S1-C19 [unit] `RegisterAuditLog` rejeita `Action` invalida

- **Dado** input `action="hack.acao"` (fora do enum)
- **Quando** `RegisterAuditLogUseCase.Execute`
- **Entao** retorna `domain.ErrInvalidAction`
- **E** nenhuma linha persistida; metric `status="error"` incrementa.
- **Tipo:** `unit`.

#### S1-C20 [unit] `RegisterAuditLog` rejeita `actor_email` vazio

- **Dado** input com `actor_email=""`
- **Quando** Execute
- **Entao** retorna `domain.ErrActorEmailRequired`.
- **Tipo:** `unit`.

#### S1-C21 [unit] `RegisterAuditLog` rejeita `IP` vazio

- **Dado** input com `IP=""`
- **Quando** Execute
- **Entao** retorna `domain.ErrIPRequired`.
- **Tipo:** `unit`.

### Seguranca (OWASP)

#### S1-C22 [CRITICO] [unit] `Metadata` com chaves proibidas e sanitizado em `RegisterAuditLog`

- **Dado** input `metadata={"reason":"x","password":"123","token":"abc","secret":"y","authorization":"Bearer z","password_hash":"hh"}`
- **Quando** Execute persiste
- **Entao** `audit_log.metadata={"reason":"x"}` (todas as chaves proibidas removidas, mesmo que caller envie).
- **Tipo:** `unit`.

#### S1-C23 [unit] `BuildDiff` ignora chaves proibidas e `updated_at`/`password_hash`

- **Dado** before=`{name:"A", password_hash:"h1", updated_at:"t1"}`, after=`{name:"B", password_hash:"h2", updated_at:"t2"}`
- **Quando** `BuildDiff(before, after)`
- **Entao** retorna `{fields:{name:{before:"A",after:"B"}}}` (nem `password_hash` nem `updated_at` aparecem).
- **Tipo:** `unit`.

## Story 2 — Detalhes capturados em cada log

### Happy path

#### S2-C01 [CRITICO] [integration] Campos obrigatorios preenchidos em todos os tipos de acao

- **Dado** registros das 14 acoes do enum
- **Quando** consulta `SELECT * FROM audit_logs`
- **Entao** todas as linhas tem `id`, `actor_email`, `action`, `ip`, `created_at` NOT NULL.
- **Tipo:** `integration`.

#### S2-C02 [CRITICO] [unit] `tenant_id` NULL em acoes do admin global sem tenant alvo

- **Dado** ao executar `auth.login.success`, `auth.login.failure`, `auth.logout`, `tenant.created`, `user_admin.created`
- **Quando** persistido
- **Entao** linha tem `tenant_id IS NULL`.
- **Tipo:** `unit` + `integration`.

#### S2-C03 [CRITICO] [unit] `user_id` NULL + `actor_email` preenchido em falha de login

- **Dado** falha de login com email inexistente (S1-C13)
- **Quando** persistido
- **Entao** `user_id IS NULL`, `actor_email="naoexiste@x.com"`.
- **Tipo:** `unit` + `integration`.

#### S2-C04 [unit] `actor_email` e snapshot mesmo se usuario for deletado depois

- **Dado** log gerado com `user_id=<id_ana>`, `actor_email="ana@crm.com"`
- **E** depois `ana@crm.com` e hard-deleted da tabela `users`
- **Quando** consulta o `AuditLog` antigo
- **Entao** `actor_email` continua `"ana@crm.com"` (snapshot — sem FK), `user_id` continua `<id_ana>` (orfao por design).
- **Tipo:** `integration`.

#### S2-C05 [CRITICO] [integration] `created_at` em UTC, com precisao de milissegundos

- **Dado** log inserido em `2026-04-24T17:32:10.123Z`
- **Quando** persistido em MySQL `TIMESTAMP(3)`
- **Entao** valor lido = `2026-04-24 17:32:10.123 UTC`; UI converte para BRT na exibicao.
- **Tipo:** `integration`.

#### S2-C06 [CRITICO] [integration] `created_at` imutavel (nao atualizado em leituras)

- **Dado** log com `created_at=t1`
- **Quando** repositorio executa `FindByID` e `List` multiplas vezes
- **Entao** `created_at` permanece `t1`.
- **Tipo:** `integration`.

### Casos de borda

#### S2-C07 [unit] `UserAgent` truncado em 255 caracteres

- **Dado** input com `user_agent` de 500 chars
- **Quando** `RegisterAuditLog.Execute`
- **Entao** persiste exatamente 255 chars.
- **Tipo:** `unit`.

#### S2-C08 [unit] `UserAgent` com control chars (`\r\n\t`) sanitizado

- **Dado** `user_agent="Mozilla\r\n<script>"`
- **Quando** Execute
- **Entao** `\r`, `\n`, `\t` substituidos por espaco.
- **Tipo:** `unit`.

#### S2-C09 [unit] `IP` invalido cai para `"invalid"` (sem rejeitar)

- **Dado** input `ip="nao-eh-ip"`
- **Quando** Execute
- **Entao** persiste com `ip="invalid"` (defesa em profundidade — nao pode bloquear auditoria por IP malformado).
- **Tipo:** `unit`.

#### S2-C10 [unit] IPv6 valido aceito sem alteracao

- **Dado** `ip="2001:db8::1"`
- **Quando** Execute
- **Entao** persiste literal `"2001:db8::1"` (coluna VARCHAR(45)).
- **Tipo:** `unit`.

#### S2-C11 [integration] Diff de update ignora `updated_at`

- **Dado** before/after com mesmo `name` mas `updated_at` diferente
- **Quando** caso de uso de update publica
- **Entao** `metadata.fields={}` (vazio, nenhuma mudanca real).
- **Tipo:** `unit`.

### Casos de erro

#### S2-C12 [unit] Tentativa de gravar `Action` fora do enum retorna `ErrInvalidAction`

- (idem S1-C19; reforcar leitura via teste de tabela com `IsValid()`).
- **Tipo:** `unit`.

### Seguranca (OWASP)

#### S2-C13 [CRITICO] [unit] Sanitizacao defensiva no `RegisterAuditLog` mesmo sem `BuildDiff`

- **Dado** caller passa `metadata={"password":"x","reason":"y"}` direto (sem BuildDiff)
- **Quando** Execute
- **Entao** `password` removido antes do INSERT; `reason` preservado.
- **Tipo:** `unit`.

#### S2-C14 [unit] Sanitizacao no `BuildDiff` mesmo se before/after vierem com chave proibida

- **Dado** before/after com `token` diferente
- **Quando** `BuildDiff`
- **Entao** `token` nao aparece no diff (pois nem chega no metadata).
- **Tipo:** `unit`.

## Story 3 — Consulta e filtro de logs (admin)

### Happy path

#### S3-C01 [CRITICO] [http] Listagem default mostra registros mais recentes primeiro

- **Dado** que existem 50 logs com timestamps variados nas ultimas 24h
- **Quando** admin faz `GET /admin/logs` (sem filtro, sem page)
- **Entao** retorna HTTP 200 com `audit/list.html`, exibindo 25 logs ordenados por `created_at DESC`, total=50, "Mostrando 1-25 de 50".
- **Tipo:** `http` + `integration`.

#### S3-C02 [http] Listagem usando header `HX-Request: true` retorna fragmento

- **Dado** mesmo cenario, mas request com `HX-Request: true`
- **Quando** GET `/admin/logs`
- **Entao** resposta e o fragmento `audit/list_table.html` (sem layout completo, apenas `<table>` + paginacao).
- **Tipo:** `http`.

#### S3-C03 [CRITICO] [http] Filtro por tenant_id retorna apenas logs daquele tenant

- **Dado** logs distribuidos: 10 com `tenant_id=A`, 5 com `tenant_id=B`, 3 com `tenant_id=NULL`
- **Quando** GET `/admin/logs?tenant_id=aaaaaaaa-...`
- **Entao** retorna 10 logs (todos com `tenant_id=A`).
- **Tipo:** `http` + `integration`.

#### S3-C04 [CRITICO] [http] Filtro por user_id retorna apenas logs daquele autor

- **Dado** logs do `admin@crm.com` (8) e `ana@crm.com` (3)
- **Quando** GET `/admin/logs?user_id=<id_ana>`
- **Entao** retorna 3 logs.
- **Tipo:** `http`.

#### S3-C05 [CRITICO] [http] Filtro por acao especifica

- **Dado** logs com diferentes actions
- **Quando** GET `/admin/logs?action=tenant.blocked`
- **Entao** retorna apenas logs com `action="tenant.blocked"`.
- **Tipo:** `http`.

#### S3-C06 [CRITICO] [http] Filtro por periodo (from + to) inclusive

- **Dado** logs em 2026-04-20, 2026-04-22, 2026-04-24
- **Quando** GET `/admin/logs?from=2026-04-22&to=2026-04-24`
- **Entao** retorna apenas logs de 22, 23 e 24 (interpretando `to` como fim do dia 23:59:59.999).
- **Tipo:** `http` + `integration`.

#### S3-C07 [CRITICO] [http] Filtros combinados (tenant + acao + periodo)

- **Dado** 100 logs variados
- **Quando** GET `/admin/logs?tenant_id=A&action=tenant.blocked&from=2026-04-22&to=2026-04-24`
- **Entao** retorna intersecao correta (ex.: 2 logs).
- **Tipo:** `http` + `integration`.

#### S3-C08 [http] Paginacao primeira pagina

- **Dado** 60 logs
- **Quando** GET `/admin/logs?page=1&page_size=25`
- **Entao** retorna logs 1-25, total=60, "Pagina 1 de 3".
- **Tipo:** `http`.

#### S3-C09 [http] Paginacao pagina do meio

- **Dado** 60 logs
- **Quando** GET `/admin/logs?page=2&page_size=25`
- **Entao** retorna logs 26-50.
- **Tipo:** `http`.

#### S3-C10 [http] Paginacao ultima pagina parcial

- **Dado** 60 logs
- **Quando** GET `/admin/logs?page=3&page_size=25`
- **Entao** retorna logs 51-60 (10 itens), "Mostrando 51-60 de 60".
- **Tipo:** `http`.

#### S3-C11 [CRITICO] [http] Contagem total correta com filtros aplicados

- **Dado** 1.247 logs no banco; filtro reduz a 12
- **Quando** GET `/admin/logs?action=permission.changed`
- **Entao** template mostra "Mostrando 1-12 de 12" (total reflete filtro, nao tabela inteira).
- **Tipo:** `http` + `integration`.

### Casos de borda

#### S3-C12 [CRITICO] [http] Listagem vazia (banco sem logs) renderiza estado "nenhum log registrado ainda"

- **Dado** tabela `audit_logs` vazia
- **Quando** GET `/admin/logs`
- **Entao** template `audit/empty.html` com mensagem "Nenhum log registrado ainda. Acoes de administracao aparecerao aqui."
- **Tipo:** `http` + `integration`.

#### S3-C13 [CRITICO] [http] Filtro sem resultado renderiza "nenhum log encontrado para os filtros aplicados"

- **Dado** logs existem, mas filtro nao casa nada
- **Quando** GET `/admin/logs?tenant_id=ffffffff-...&action=login.success`
- **Entao** mensagem especifica de filtro vazio + botao "Limpar filtros" visivel.
- **Tipo:** `http`.

#### S3-C14 [http] Pagina alem do total retorna pagina vazia (sem erro)

- **Dado** 60 logs, page_size=25 (3 paginas)
- **Quando** GET `/admin/logs?page=99`
- **Entao** retorna HTTP 200 com lista vazia + paginacao indicando "Pagina 99 de 3" (ou similar) sem 500.
- **Tipo:** `http`.

#### S3-C15 [http] Periodo `from` igual a `to` (mesmo dia)

- **Dado** 5 logs em 2026-04-24
- **Quando** GET `/admin/logs?from=2026-04-24&to=2026-04-24`
- **Entao** retorna os 5 logs do dia.
- **Tipo:** `http`.

#### S3-C16 [http] page_size dentro dos valores permitidos (10, 25, 50, 100)

- **Dado** 200 logs
- **Quando** GET `/admin/logs?page_size=100`
- **Entao** retorna 100 logs na pagina.
- **Tipo:** `http`.

### Casos de erro

#### S3-C17 [CRITICO] [http] `from > to` retorna erro amigavel

- **Dado** request com `from=2026-04-30&to=2026-04-01`
- **Quando** GET `/admin/logs`
- **Entao** retorna HTTP 400 (ou 200 com mensagem inline) com texto "Periodo invalido: data inicial maior que data final" e nao executa SELECT.
- **E** caso de uso devolveu `domain.ErrInvalidPeriod`.
- **Tipo:** `unit` + `http`.

#### S3-C18 [CRITICO] [http] `page_size` invalido (ex.: 999) e rejeitado

- **Dado** request com `page_size=999`
- **Quando** GET `/admin/logs`
- **Entao** rejeita com mensagem "Tamanho de pagina invalido" (ou normaliza para 100 conforme decisao — confirmar com Dev/Arquiteto). Caso de uso retorna `ErrInvalidPageLimit`.
- **Tipo:** `unit` + `http`.

#### S3-C19 [http] `page` <= 0 e rejeitado/normalizado

- **Dado** `page=0` ou `page=-1`
- **Quando** GET `/admin/logs`
- **Entao** normaliza para `page=1` ou retorna 400.
- **Tipo:** `http`.

#### S3-C20 [http] `action` fora do enum e rejeitado

- **Dado** `action=hack.invalida`
- **Quando** GET `/admin/logs?action=hack.invalida`
- **Entao** retorna 400 com "Acao invalida" (ou ignora filtro — confirmar com Arquiteto).
- **Tipo:** `http`.

#### S3-C21 [http] `tenant_id` malformado (nao-UUID) e rejeitado

- **Dado** `tenant_id=abc`
- **Quando** GET `/admin/logs?tenant_id=abc`
- **Entao** retorna 400 com "Tenant invalido".
- **Tipo:** `http`.

#### S3-C22 [http] Datas malformadas em `from`/`to` rejeitadas

- **Dado** `from=24-04-2026` (formato invalido)
- **Quando** GET `/admin/logs?from=24-04-2026`
- **Entao** retorna 400 com "Data invalida (use YYYY-MM-DD)".
- **Tipo:** `http`.

### Seguranca (OWASP)

#### S3-C23 [CRITICO] [http] SQL injection em `action` nao executa SQL

- **Dado** `action="' OR 1=1 --"`

## Observacoes para Dev/Arquiteto

1. **Comportamento esperado para `page_size` invalido (S3-C18):** o design diz "max 100" mas nao especifica se valores fora rejeitam (400) ou clamp (normaliza para 100). Cenario S3-C18 assume rejeicao via `ErrInvalidPageLimit`. **Confirmar com Arquiteto antes de implementar o handler.**
2. **Comportamento para `action` fora do enum em filtro (S3-C20):** rejeitar com 400 ou ignorar silenciosamente? Atual cenario assume rejeicao. **Confirmar com Arquiteto.**
3. **Resposta de `/admin/logs` para nao autenticado (S5-C04):** o design implica reuso de `mw.Auth` que hoje devolve 401 JSON; o wireframe sugere redirect para `/admin/login`. Manter o que `mw.Auth` ja faz para o resto do admin — **PO/UX confirmar se 401 JSON e aceitavel ou se precisa do redirect HTML para esta tela.**
4. **Acesso negado por nao-admin gera audit log proprio? (S5-C15):** Story 5 criterio 5 diz "podem". Arquiteto definiu MVP **sem** esse registro. QA aceita; **Seguranca pode pedir reativacao no review** — se pedir, adicionar `Action="access.denied"` no enum.
5. **`tenant_id` em `permission.changed`:** o mapa de eventos do design (4.3) diz "tenant alvo se houver" — para alvo admin o tenant_id e NULL; para alvo de tenant (fora do escopo MVP — S1-C15) seria preenchido. **Confirmar que apenas alvo admin entra no MVP.**
6. **Botao "Limpar filtros" em estado de filtro vazio (S3-C13):** wireframe diz que o botao aparece em "destaque" no estado vazio; QA assume mesmo botao da barra de filtros, agora com classe visual diferente. **UX confirmar visual exato.**

## Decisoes do usuario (2026-04-24)

Ambiguidades resolvidas antes do inicio do Dev Backend:

1. **`page_size` invalido (obs. 1):** **clampar** para o valor maximo (100) quando > 100; clampar para 10 (default) quando <= 0 ou nao-numerico. Nao retornar 400. Atualizar S3-C18 para esperar clamp ao inves de erro.
2. **`action` fora do enum em filtro (obs. 2):** **rejeitar com 400** e mensagem `action invalida`. Mantem S3-C20 como esta.
3. **Nao autenticado em `/admin/logs` (obs. 3):** **redirect HTML** para `/admin/login?return=...` (eh tela de UI, nao API). Dev Backend deve usar helper de redirect do admin (ou criar um se nao existir), nao o `mw.Auth` JSON 401. Atualizar S5-C04 para esperar 302 + Location.
4. **`access.denied` audit log (obs. 4):** mantido **fora do MVP**. Seguranca pode pedir reativacao no review.
5. **`permission.changed` alvo (obs. 5):** **apenas alvo admin** no MVP — `tenant_id` sempre NULL para esta acao.
6. **Botao "Limpar filtros" vazio (obs. 6):** deixar Dev Front-end decidir com base no wireframe — cosmetico.
