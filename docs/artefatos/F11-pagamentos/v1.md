## Entregue

### Domínio (`internal/pagamentos/domain/`)
- Entidade `Payment` com transições explícitas (`MarkAsPaid`, `Cancel`) + auditoria (`PaidByUserID`, `PaidAt`, `CancelledByUserID`, `CancelledAt`, `Observacao`).
- `BillingConfig` do tenant com `Plan` enum (`mensal`/`anual`/`vitalicio`/`externo`), valor em centavos, dia (1-28), data de início e flag de exibição.
- `BrazilHolidayCalendar` thread-safe com cache por ano; feriados fixos + móveis (Páscoa via Meeus/Jones/Butcher); `NextBusinessDay` e `AddBusinessDays`.

### Application
- Mutações: `RegisterManualPayment`, `MarkPaymentAsPaid`, `CancelPayment`.
- Leitura: `ListTenantPayments`, `ListAllPayments`, `GetTenantFinancialSummary` (badge + 3 métricas).
- Cron: `GenerateRecurringPayments` (competências faltantes respeitando `DataInicioCobranca` + prorrogação para próximo dia útil) e `RefreshOverdueStatuses` (marca atrasado quando `DataVencimento + grace_days (úteis)` passou).
- Traces OTel (`pagamentos`) em todos os UCs com atributos `tenant_id`, `payment_id`, `user_id`, `valor_cents`, `created`, `updated`.

### Infra
- `GormPaymentRepository` com unique `(tenant_id, tipo=recorrente, competencia)` + `ExistsRecorrente` usando `DATE(?)`.
- `GormTenantBillingRepository` lê direto da tabela `tenants` sem acoplar ao pacote `tenant`.
- `BillingScheduler` com `robfig/cron/v3`, logging estruturado (`request_id = cron-billing-<uuid>`) e métricas Prometheus.
- Métricas: `pagamentos_cron_runs_total`, `pagamentos_cron_duration_seconds`, `pagamentos_recorrentes_gerados_total`, `pagamentos_atualizados_atrasado_total`, `pagamentos_marcados_pago_total`, `pagamentos_lancados_avulso_total`, `pagamentos_cancelados_total`.

### Migrations
- `000054_alter_tenants_billing` — adiciona 5 colunas de cobrança em `tenants`.
- `000055_create_payments` — tabela `payments` + FK + unique + índices de consulta.

### UI
- **Admin**: `/admin/pagamentos` (global, filtros tenant/status/data), `/admin/tenants/:id/pagamentos` (aba por tenant com resumo financeiro e botão "Novo lançamento"), `POST /pagamentos/:id/pagar`, `POST /pagamentos/:id/cancelar`, modal HTMX para avulso.
- **Portal tenant**: `GET /pagamentos` read-only; middleware `PortalAccessChecker` valida plano cobrável + `exibir_pagamentos=true` + permissão via `permission.Resolver` (owner bypass + admin bypass + `payments:view`).
- Templates em `web/templates/pagamentos/` (full pages + partials `resumo_financeiro.html`, `payment_row.html`, `row_admin.html`).
- CSS em `web/static/css/main.css` (tabela, badges, filtros, modal, resumo).
- Sidebar admin e tenant ganham item "Pagamentos".

### Permissões
- Novo resource `payments` com ação `view` em `internal/permission/domain/permission.go`.

## Ajustes ao plano durante a execução
- **Páscoa**: algoritmo Meeus/Jones/Butcher usa `l = ... % 7` (não `% 30` como no rascunho). Já corrigido.
- **Calendário thread-safe**: `sync.RWMutex` com double-check pattern. Essencial porque o calendário é compartilhado entre cron e handlers HTTP.
- **`ExistsRecorrente`**: usa `competencia = DATE(?)` para contornar mismatch DATE/DATETIME quando DSN usa `loc=Local`.
- **Tenant `ExibirPagamentos`**: struct tag GORM `default:true` removida (GORM trata `false` como "unset" e deixava MySQL default sobrescrever). Default fica no banco via migration.
- **DATE-roundtrip**: tenant `toModel` normaliza `DataInicioCobranca` para local-midnight preservando Y/M/D — resolve duplicação de competências por shift TZ.
- **Erros de billing na UI**: retornam 200+form error (convenção HTMX do projeto), não 422 como sugerido no rascunho do plano.
- **Template loader**: passou a usar múltiplos globs (1, 2, 3 níveis) porque `filepath.Glob` do Go não suporta `**` recursivo.
- **Portal menu**: item "Pagamentos" sempre visível na sidebar tenant — middleware trata negação (404 sem vazar). Alternativa seria injetar `ShowPagamentos` em todos os handlers tenant, muito invasivo.
